  理由：

  1. 当前架构的问题

  cardDataProvider 是一个"被动"的 store，需要外部调用 setEntries()
  才能更新。这导致必须有一个桥接代码来调用它——而这个桥接本质上只是把
  wordSelectionProvider 的状态转换成 CardEntryModel。多了一层不必要的间接。

  2. 推荐方案：选中状态 + 衍生数据合一

  wordSelectionProvider (增强)
  ├── tokens          ← 分词结果
  ├── selectedIndices ← 选中索引
  ├── selectedText    ← 拼接文本（已有计算属性）
  └── currentEntry    ← 新增：从选中状态 + 剪贴板 + 翻译 自动派生

  选中变化 → wordSelectionProvider 状态更新
           → currentEntry 自动重算（word/example/翻译 从自身状态 +
  clipboardProvider 派生）
           → ResultsList 直接 watch → UI 刷新

  - ResultsList 极简：只管 ref.watch(wordSelectionProvider).currentEntry
  拿数据渲染，不参与数据构建
  - 无桥接代码：不需要监听一个 provider 再手动调用另一个 provider 的 setEntries
  - 未来扩展清晰：Phase 2 加词典查询时，在 currentEntry 的计算逻辑后追加"查词典
  → 追加释义条目"即可，数据流方向不变
