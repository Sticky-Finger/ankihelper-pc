⏺ 你的直觉是对的。导入模板不需要 Anki 打开。

  当前实现的问题：importFromFile 把两件不同的事绑在一起了——

  ┌───────────────────────────────┬───────────────┬─────────────┐
  │             步骤              │     本质      │ 需要 Anki？ │
  ├───────────────────────────────┼───────────────┼─────────────┤
  │ 解析 HTML + 存本地            │ 本地文件操作  │ 不需要      │
  ├───────────────────────────────┼───────────────┼─────────────┤
  │ _registerToAnki (createModel) │ 远程 API 调用 │ 需要        │
  └───────────────────────────────┴───────────────┴─────────────┘

  但注册到 Anki 这一步完全可以延迟到添加卡片时再做。实际上代码里已经有
  TemplateManager.ensureModelExists() 这个方法，它在 _addNoteToAnki
  里被调用——添加卡片前检查模型是否存在，不存在才创建。

  所以正确的设计是：

  1. 导入时：只做本地解析 + 存储，不碰 Anki
  2. 添加卡片时：ensureModelExists() 自动处理注册

  这样用户即使没打开
  Anki，也能顺利导入模板、配置字段映射，等实际添加卡片时再连接 Anki。

  另外你提到的错误提示被设置弹窗挡住的问题，也是因为现在导入失败直接抛异常，而
  SnackBar 显示在设置弹窗后面。如果导入不再依赖
  Anki，这个错误场景基本就不会出现了。

  要不要我修一下这个设计？改动范围很小——只需要从 importFromFile 里移除
  _registerToAnki 调用。

⏺ 看完代码，两个问题的原因很清楚：

  为什么 Anki 里有 4 个不同名称的模板

  _registerToAnki (template_manager.dart:158-159) 有防重复逻辑：

  final existingModels = await service.getModelNames();
  if (existingModels.contains(name)) return;  // 同名则跳过

  所以同名模板不会重复创建。但你在 app 里每次导入时，_getUniqueTemplateName
  会自动追加后缀（vocabulary_card_model → -1 → -2 →
  -3），导致每次导入都用了不同的名字注册到 Anki，于是 Anki 里就出现了 4 个模板。

  为什么 app 里删除模板，Anki 里的没消失

  removeTemplate (template_provider.dart:114-142) 只做了两件事：
  1. 从本地 _templates 列表移除
  2. 从 SharedPreferences 移除持久化路径

  完全没有调用 AnkiConnect 去删除 Anki 中的模型。 AnkiConnect 有 deleteModel
  action，但当前代码没用它。

  ---
  总结当前设计的两个问题：

  ┌───────────────────────────┬─────────────────────────────────────────────┐
  │           问题            │                    原因                     │
  ├───────────────────────────┼─────────────────────────────────────────────┤
  │ 导入模板必须开 Anki       │ importFromFile 把本地解析和远程注册绑在一起 │
  ├───────────────────────────┼─────────────────────────────────────────────┤
  │ app 删除模板不同步到 Anki │ removeTemplate 只删本地，不调 AnkiConnect   │
  └───────────────────────────┴─────────────────────────────────────────────┘

  要我一并修这两个问题吗？改动很小：
  1. importFromFile 去掉 _registerToAnki 调用（延迟到 ensureModelExists）
  2. removeTemplate 加上 deleteModel 调用（同步删除 Anki 中的模型）

            └─ 字段不匹配 →

                b. 用新名 createModel
                c. 添加卡片
                d. 返回信息："模板名称已改为 <新名>"

     关键点:
     - 模板名不匹配时：直接创建，简单
