⏺ 分析结果：

  根本原因：macOS 的 App Transport Security (ATS) 限制

  macOS/iOS 默认不允许 HTTP 请求，只允许 HTTPS。用户添加的自定义发音源使用的是
  http:// 协议，被系统阻止了。

  证据：
  1. URL 是 http://dict.youdao.com/dictvoice?audio=test&type=2（HTTP）
  2. 错误发生在 Darwin（macOS）平台
  3. 内置的有道发音源使用 https:// 协议，之前测试通过

  解决方案：

  在 macos/Runner/Info.plist 中添加 ATS 例外配置，允许 HTTP 请求：

  <key>NSAppTransportSecurity</key>
  <dict>
      <key>NSAllowsArbitraryLoads</key>
      <true/>
  </dict>

  或者，更安全的做法是只允许特定域名的 HTTP 请求：

  <key>NSAppTransportSecurity</key>
  <dict>
      <key>NSExceptionDomains</key>
      <dict>
          <key>dict.youdao.com</key>
          <dict>
              <key>NSExceptionAllowsInsecureHTTPLoads</key>
              <true/>
          </dict>
      </dict>
  </dict>

  建议：
  1. 方案 1：修改 Info.plist 允许所有 HTTP 请求（简单但安全性较低）
  2. 方案 2：修改 Info.plist 只允许特定域名（更安全）
  3. 方案 3：在添加自定义发音源时验证 URL 必须是
  HTTPS（不修改系统配置，但限制用户选择）

  你倾向哪个方案？
