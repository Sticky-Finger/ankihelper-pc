  发音服务需求分析

  现状

  1. 模板已有 发音 字段 — assets/template01/vocabulary_card_model.html
  第8行：{{音标}} {{发音}}，背面模板的第165行也声明了 发音 字段
  2. 字段映射未包含 发音 — vocabulary_card_model.json 的 fieldMapping 中没有映射
   发音，所以目前这个字段生成卡片时是空的
  3. CardEntryModel 没有发音字段 — 只有
  word/phonetic/pos/meaning/example/exampleTranslation，没有发音URL

  有道发音 API

  有道词典提供免费的发音接口（无需鉴权）：
  https://dict.youdao.com/dictvoice?audio={单词}&type={0=英音|1=美音}
  这是一个 GET 请求返回音频文件，可以直接拼装 URL 填入卡片字段。

  实现方案

  有两种思路：

  方案 A：服务层自动填充（推荐）
  - 新增 PronunciationService，根据单词拼装有道发音 URL
  - 在 CardEntryModel 中增加 pronunciationUrl 字段
  - 在 template_manager.dart 的 buildFields() 或上游调用处，将发音 URL 注入到
  发音 字段

  方案 B：完全在模板侧处理
  - 不在 Dart 层处理，而是在 Anki 卡片模板中用 JavaScript 或 {{#字段}}
  条件判断动态拼接
  - 缺点是 Anki 模板中做 HTTP 请求较复杂，且依赖网络

  需要讨论的点

  1. 英音 vs 美音：默认用哪个？建议用美音（type=1），更普遍
  2. 是否需要用户配置：是否需要让用户在设置面板选择英音/美音？还是先做死为美音，
  以后扩展
  3. 发音字段名映射：模板里字段名是 发音，是否需要在 _knownFieldNames 中加一个
  '发音': 'pronunciationUrl'?
  4. 离线时的行为：如果没网络，发音字段留空不填充

  你觉得这些方向怎么样？确认后我写 plan 文档。
